# Policy Q&A Assistant with Evidence

An evidence-first FastAPI application for a small controlled collection of company policy documents. It answers only when retrieved policy text is sufficiently relevant, gives traceable citations, exposes retrieval debugging, and stores every question for review.

The browser application is served at `http://127.0.0.1:8000/` after startup. It includes policy upload, evidence cards, agent traces, citations, and question suggestions. To use Gemini for grounded drafting, set `GEMINI_API_KEY` and `ENABLE_LLM=true`; citation and evidence checks remain mandatory. Without it, the same agent workflow uses an offline extractive fallback.

## Run

```powershell
cd policy-qa-assistant
..\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:PYTHONPATH = "src"
python scripts/ingest_policies.py
uvicorn policy_qa_assistant.main:app --reload --port 8000
```

Run the automated checks with `python -m pytest`.

## API

| Endpoint | Purpose |
| --- | --- |
| `POST /documents/ingest` | Upload a PDF, DOCX, Markdown, or text policy. Duplicate files are rejected. |
| `GET /documents` | List ingested documents. |
| `POST /questions` | Ask a question. Body: `{"question":"...", "top_k":5, "document_ids":["upload-id"]}`. `document_ids` is optional; when provided, only those uploaded policies are searched. |
| `GET /questions/{id}` | Fetch a stored response. |
| `GET /questions/{id}/debug` | See query, chunks, scores, final context, answer, and citations. |
| `POST /evaluation/run` | Run the small reproducible smoke evaluation. |

The question response always has `answer`, `supported`, `citations`, `retrieved_sources`, `confidence`, and `reason_for_refusal`. A refusal has no citations and says why support was insufficient.

## Included artefacts

- Six short numbered policies in `data/policies/`
- `data/document_manifest.json`
- Evaluation set in `evaluation/questions.json`
- Repeatable ingestion script in `scripts/ingest_policies.py`
- 23 automated tests in `tests/test_policy_qa.py`, including multi-document,
  ambiguity, conflict, citation, duplicate, empty-result, and terminology cases
- Reproducible metrics in `evaluation/latest_results.json` and three retrieval
  traces in `evaluation/debug_examples.json` (generated by `POST /evaluation/run`)

## Design notes

Chunks retain document and section metadata. The application creates and persists deterministic local embeddings in `data/vector_store/policy_index.json`, so it works offline and does not need an LLM API key. The final answer is extracted from retrieved policy passages; it is never completed from general model knowledge. Re-run `python scripts/ingest_policies.py` to rebuild the derived index from the six supplied documents.
